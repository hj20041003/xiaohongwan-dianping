# 小红碗点评 · 面试八股问题清单（含答案要点）

> 按模块分类，共 8 大类 52 题。⭐ = 高频必背。答题要点为浓缩版，面试时展开 1-2 分钟。

## 一、项目与架构（必问）

**Q1 ⭐ 介绍一下你的项目？**
要点：一句话定位（本地生活点评平台）→ 技术栈（Spring Cloud 微服务：Nacos/Gateway/Feign + Redis + Vue2）→ 核心功能三句话（登录/笔记社区/商户与营销）→ 一个亮点收尾（Redis 多场景应用或微服务拆分思路）。

**Q2 ⭐ 为什么用微服务？单体不行吗？**
要点：①按领域拆分，独立部署、故障隔离 ②团队并行开发 ③按服务弹性扩缩容。**反问补丁**：单体并非不行，小规模单体更快；本项目为演示微服务治理体系（注册发现/网关/远程调用）而拆分，且拆分粒度适中、避免过度拆分。

**Q3 服务怎么拆分的？依据是什么？**
要点：按业务领域拆——用户（身份）、商户（POI 资产）、笔记（内容社区）、优惠券（营销）。依据：数据模型不同、变更频率不同、未来扩容需求不同。消息/关注因强依赖笔记数据，并入 blog 服务（避免过度拆分）。

**Q4 服务之间怎么通信？为什么用 Feign 而不是 RestTemplate？**
要点：OpenFeign 声明式调用（接口+注解），底层默认 HTTP；集成 Ribbon/LoadBalancer 做客户端负载均衡。Feign 优点：像调本地方法一样调远程、易于超时/重试/日志配置。本项目场景：blog 服务批量查作者信息。

**Q5 两个服务分别有自己的数据库，跨服务怎么关联查询？**
要点：**禁止跨库 join**。方案：①Feign 调用对方接口批量取数据（本项目：笔记作者昵称头像）②数据冗余（下单快照）③汇总到搜索/数仓。重点讲**避免 N+1 远程调用**：收集 id 去重后一次批量查询，内存组装。

## 二、Nacos / 注册中心

**Q6 ⭐ Nacos 的注册与发现原理？**
要点：服务启动时向 Nacos 注册（服务名→IP:Port）；消费者拉取服务列表并本地缓存 + 订阅变更推送（2.x 用 gRPC 长连接推送）。临时实例靠**心跳**保活（默认 5s 一次，15s 未收到标记不健康，30s 剔除）。

**Q7 Nacos 是 AP 还是 CP？**
要点：**默认 AP**（临时实例，Distro 协议）；持久化实例/配置中心走 CP（Raft）。服务发现要可用性优先，所以默认 AP——挂掉的服务不会立刻不可查，靠健康检查剔除。

**Q8 ⭐ 你遇到过服务注册 IP 不对的问题吗？（项目真实案例）**
要点：多网卡机器（VMware 虚拟网卡）上 Nacos 客户端可能选错网卡 IP 注册，导致网关转发超时。解决：`spring.cloud.nacos.discovery.ip=127.0.0.1` 显式指定。延伸：生产用 `INetAddress` 策略或内网 IP 段配置。

**Q9 Nacos 和 Eureka 的区别？**
要点：①Nacos 支持 CP/AP 切换，Eureka 仅 AP ②Nacos 2.x gRPC 长连接推送，Eureka 客户端 30s 拉取 ③Nacos 还有配置中心功能 ④Eureka 2.0 已停更。

## 三、Gateway / 网关

**Q10 ⭐ 网关的作用？你的网关做了什么？**
要点：统一入口、动态路由、协议转换、鉴权限流等横切能力。本项目：按路径前缀路由到 4 个服务（lb:// 负载均衡）+ 全局日志过滤器（GlobalFilter 记录耗时）；预留统一鉴权扩展点。

**Q11 Gateway 为什么用 WebFlux？和 Zuul 区别？**
要点：Gateway 基于 Netty+WebFlux 响应式非阻塞模型，线程少、吞吐高；Zuul 1.x 是阻塞 IO（一请求一线程）。Zuul 2.x 虽异步但 Spring 生态支持弱。

**Q12 网关转发时 500/超时怎么排查？（项目真实案例）**
要点：看网关日志定位目标 IP → 发现注册的是虚拟网卡 IP → 说明**服务发现给的地址不可达**。方法论：先分清"网关的问题"还是"下游的问题"（直连下游测试）。

## 四、Redis（高频重灾区）

**Q13 ⭐ 你的项目里 Redis 用在哪些地方？**
要点：①登录 Token 会话（String + TTL）②验证码（String + 2min TTL）③点赞用户集合（ZSet，score=时间戳，天然去重+排序）④Feed 流推送（ZSet 按时间线）⑤商户缓存（预留）。**体现"一个 Redis 多种数据结构多种场景"**。

**Q14 ⭐ 为什么登录态用 Redis Token 而不是 Session？**
要点：Session 存在单机内存，微服务多实例间不共享（需要粘性会话或 Session 复制）；Redis 集中式存储→**任意实例都能验证→无状态水平扩展**；且 Token 方案适合 APP/小程序多端。

**Q15 ⭐ 缓存穿透、击穿、雪崩及解决方案？**
要点：**穿透**（查不存在的数据，绕过缓存打库）→ 缓存空值/布隆过滤器；**击穿**（热点 key 过期瞬间大量请求打库）→ 互斥锁重建/逻辑过期；**雪崩**（大量 key 同时过期）→ 过期时间加随机值/多级缓存/熔断降级。本项目商户缓存实现了"缓存空值+互斥锁"两套方案（教学项目核心）。

**Q16 Redis 为什么快？**
要点：①纯内存 ②单线程无锁竞争（6.0 后网络 IO 多线程）③IO 多路复用（epoll）④高效数据结构（SDS/跳表/压缩列表）。

**Q17 Redis 持久化方式？**
要点：RDB（快照，恢复快，可能丢数据）+ AOF（追加日志，丢数据少，文件大）；4.0 后混合持久化（RDB 头+AOF 尾）。缓存场景可只开 RDB 或按业务容忍度配置。

**Q18 Redis 过期删除策略与内存淘汰策略？**
要点：过期删除=**惰性删除+定期删除**组合；内存满时按 maxmemory-policy 淘汰（noeviction/allkeys-lru/volatile-lru/allkeys-lfu 等），缓存场景常用 allkeys-lru。

**Q19 点赞为什么用 ZSet 不用 Set？**
要点：ZSet 多了 score（存点赞时间戳）→ 支持"按时间排序点赞列表""是否点赞 O(1)（zscore）""共同点赞"等需求，Set 只能去重不能排序。

**Q20 ⭐ Redis 和数据库双写一致性怎么保证？**
要点：主流方案 **Cache Aside**：读→先缓存后库；写→先更新库，再**删除**缓存（不是更新）。延迟双删应对并发不一致；要求强一致则用分布式锁+订阅 binlog（Canal）兜底。承认"缓存与库强一致很难，最终一致+容忍短暂不一致"是成熟回答。

**Q21 Redis 分布式锁怎么实现？有什么问题？**
要点：SET NX EX + 唯一值 + Lua 保证"判断+删除"原子性；问题：锁过期业务没执行完（看门狗续期，Redisson）、主从切换锁丢失（RedLock 争议）。本项目商户缓存互斥锁用了此方案。

## 五、数据库 / MyBatis-Plus

**Q22 ⭐ 为什么演示环境用 H2？生产怎么迁移？**
要点：H2 零安装、秒级启动、MySQL 兼容模式保证 SQL 通用性，适合演示与 CI；迁移生产改 JDBC 驱动+连接串即可（MyBatis-Plus 屏蔽方言差异），分页插件配置对应方言。

**Q23 MyBatis-Plus 的主键策略有哪些？（项目真实案例）**
要点：AUTO（数据库自增）、INPUT（手动）、ASSIGN_ID（雪花算法）、ASSIGN_UUID。**踩坑**：业务主键（如 user_id 即主键）用 AUTO 会丢弃手动值导致 insert 缺主键，必须 INPUT——本项目真实踩坑。

**Q24 MyBatis-Plus 分页原理？**
要点：PaginationInnerInterceptor 拦截器改写 SQL（自动拼 LIMIT + COUNT 查询）。注意：多租户/排序等也可用拦截器链实现。

**Q25 ⭐ 你的查询接口怎么做的排序？（项目）**
要点：距离排序用**经纬度平面近似**（(x-x₀)²+(y-y₀)²）在 SQL ORDER BY 完成，避免全量拉内存排序；精确距离用 Haversine，海量数据用 Redis GEO（GEOSEARCH）或 ES。

**Q26 什么字段适合建索引？（结合项目）**
要点：高频查询条件+高区分度：tb_shop 的 type_id、（address/name 前缀索引或全文索引）、tb_blog 的 user_id、tb_message 的 user_id+is_read 联合索引。避免区分度低的列（如 gender）。

**Q27 数据库三大范式？你反范式了吗？**
要点：1NF 原子性、2NF 消除部分依赖、3NF 消除传递依赖。**反范式场景**：tb_blog 冗余 liked/comments 计数字段（避免每次聚合统计），用增量 SQL 维护——空间换时间。

## 六、登录 / 安全

**Q28 ⭐ 你的登录流程完整讲一遍？**
要点：前端提交手机号→后端生成 6 位随机码存 Redis（TTL 2min，演示直接回显，生产走短信网关）→用户提交手机号+验证码→校验 Redis 中的码（一次性，用后删）→查库无此用户则自动注册→生成 UUID Token→用户信息 JSON 存 Redis（TTL 10h）→返回 token；前端存 sessionStorage，后续请求带 authorization 头。

**Q29 Token 方案怎么实现"服务端主动失效"？JWT 做不到的它能做什么？**
要点：JWT 自包含、无状态，但**签发后无法主动作废**（除非黑名单，又回到有状态）；Redis Token 方案删除 key 即登出/踢人。本项目改昵称/头像后同步重写 Redis 里的会话 JSON，保证信息实时。

**Q30 验证码怎么防刷？**
要点：①发送频率限制（60s 一条，前端禁用+后端 Redis 记录）②每日上限 ③图形验证码前置 ④IP 限制。演示环境直接回显验证码，生产必须接短信网关+风控。

**Q31 密码在数据库怎么存？**
要点：绝不明文，用 BCrypt（自带盐、慢哈希抗暴力）；本项目登录为验证码免密注册，预留 password 字段。

**Q32 ⭐ 网关统一鉴权怎么设计？各服务还需要拦截器吗？**
要点：两种模式：①网关统一鉴权（JWT 校验+用户信息透传 Header）②网关只路由，各服务自行校验 Redis。本项目采用 ②（Redis 集中会话天然共享），网关保留过滤器扩展点。讨论两种取舍是加分项。

## 七、前端（Vue2）

**Q33 Vue2 响应式原理？**
要点：Object.defineProperty 劫持 getter/setter + 依赖收集（Dep/Watcher）+ 数组方法重写。缺陷：新增/删除属性监听不到（$set）、数组下标赋值监听不到。Vue3 改 Proxy。

**Q34 v-model 的原理？**
要点：语法糖 = :value + @input 事件。组件上使用时默认 model: value/input，可配置 model 选项修改。

**Q35 ⭐ computed 和 watch 的区别？什么时候用哪个？**
要点：computed 有缓存、依赖不变不重算、**不能有副作用**；watch 无缓存、适合异步/开销大的操作。项目案例：管理后台"平台速览"统计（最多赞笔记/总点赞）用 computed 从列表派生。

**Q36 组件间通信方式有哪些？**
要点：props/$emit、$refs、EventBus（$on/$emit，小型项目）、provide/inject（跨层级）、Vuex（全局状态）。项目里 foot-bar 组件用 props 传 activeBtn + $emit 点击事件。

**Q37 ⭐ 中文输入法下回车搜索会误触发，怎么解决？（项目真实案例）**
要点：compositionstart/end 事件标记组词状态，keyup.enter 时检查 `e.isComposing || e.keyCode === 229` 则忽略。-element 组件用 `.native` 修饰监听原生事件。

**Q38 跨域是什么？你怎么解决的？**
要点：浏览器同源策略（协议/域名/端口任一不同）。解决方案：①后端 CORS 响应头 ②**nginx 反向代理同源化**（本项目：前端 /api 由 nginx 转发到网关，页面和接口同源，天然无跨域）③webpack devServer proxy（开发期）。

**Q39 v-if 和 v-show 的区别？**
要点：v-if 真正增删 DOM（惰性，初始开销小，切换开销大）；v-show 只切 display（初始渲染开销，频繁切换用 v-show）。项目案例：消息中心"全部已读"按钮用 v-if、返回顶部用 v-show+transition。

## 八、场景设计题（结合项目延伸）

**Q40 ⭐ 秒杀怎么设计防超卖？**
要点：①库存预热到 Redis ②Lua 脚本原子"判断库存+扣减"③判断一人一单（Set/唯一索引）④消息队列异步落库削峰 ⑤前端按钮防重+接口限流。当前项目为阻塞队列版教学实现，面试主动讲"生产如何演进"加分。

**Q41 ⭐ 消息通知怎么实现？如果做成推送呢？**
要点：当前：互动事件（点赞/评论）同步写消息表+未读数，前端进入消息页拉取。演进：轮询 → 长轮询 → **WebSocket/SSE 实时推送**；高并发下通知写 MQ 异步化，避免互动链路被通知拖慢。

**Q42 附近商户/距离排序怎么实现？**
要点：小数据量 SQL 平面近似（本项目）；标准方案 **Redis GEO**（GEOADD/GEOSEARCH BYRADIUS，底层 geohash+跳表）；超大规模用 ES geo_point 或 PD。
 
**Q43 排行榜怎么设计？**
要点：Redis ZSet 一把梭（ZINCRBY 加分、ZREVRANGE 取 TopN、ZREVZRANK 查名次）；维度多/需要深分页则用数据库落表+索引，或 ES。

**Q44 Feed 流的推模式和拉模式？**
要点：**推**（发笔记时写入所有粉丝收件箱，本项目 ZSet 实现，读快写放大）、**拉**（读时查关注者笔记合并，写简单读慢）；大 V 多用推拉结合（活跃粉丝推、普通拉）。

**Q45 ⭐ 如果流量涨 100 倍，你的项目怎么扩容？**
要点：①无状态服务水平扩容（Redis 会话已支持）②Redis 集群化 ③数据库读写分离→分库分表（按 user_id 分片）④静态资源 CDN ⑤热点接口缓存/限流（Sentinel）⑥链路压测找瓶颈。体现"演进而非推翻"。

**Q46 接口幂等性怎么保证？（结合评论/评分）**
要点：①唯一索引防重（user_id+blog_id）②Token 机制（先领令牌，提交携带，Redis 删除判断）③状态机。本项目评分采用"覆盖式"天然幂等。

**Q47 线上接口变慢怎么排查？**
要点：①定位层级（网络/网关/应用/DB）②应用：日志耗时、线程 dump ③DB：慢 SQL 日志、EXPLAIN 执行计划 ④Redis：大 key/热 key ⑤外部依赖。工具：Arthas、SkyWalking、压测 JMeter。

**Q48 你项目里 Nacos 挂了会怎样？**
要点：客户端有**本地服务列表缓存**，短时间不影响已有调用；新服务上下线感知不到；配置中心拉取不到新配置——所以生产 Nacos 集群部署（3 节点）。

## 九、基础补强（顺带被问）

**Q49 HTTP 常见状态码？你项目里用过哪些语义？**
要点：200 OK / 304 缓存 / 400 参数错 / **401 未登录（本项目未登录返回 401，前端拦截器跳登录页）** / 403 无权限 / 404 不存在 / 500 服务异常。

**Q50 Cookie、Session、Token 区别？**
要点：Cookie 存客户端随请求携带；Session 存服务端（依赖 Cookie 传 sessionId，分布式有问题）；Token 自包含/可无状态。本项目：token 在 sessionStorage（关标签页即失效，安全），Redis 侧设 TTL（10h）。

**Q51 什么是 RESTful 风格？你项目里怎么用的？**
要点：资源+方法语义：GET 查、POST 增、PUT 改、DELETE 删。项目：PUT /user/nickName、DELETE /blog/{id}、PUT /blog/like/{id}（动作语义用 PUT 也常见）。

**Q52 前后端分离的优缺点？**
要点：优点：并行开发、职责清晰、多端复用接口；缺点：SEO 弱（SPA）、联调成本（需接口文档/Swagger）、首屏加载（可 SSR 解决）。
